# Version update checklist

Version format: `<upstream base>+fukuyori.<major>.<minor>`
(e.g. `0.7.9_20260923+fukuyori.3.2`).  The base follows the upstream
`configure.ac` version after a sync; the fork number is bumped by the maintainer.

## Files to edit by hand

- `configure.ac`: `AC_INIT([gforth],[<version>],...)`  (single source of truth;
  `build-native.ps1` / `build-installer.ps1` read PACKAGE_VERSION from here)
- `README.md`: lines 6-7 (base version and current release version)
- `docs/WINDOWS-NATIVE.md`: lines 6-7 (base version and current release version)
- `docs/LICENSE-NOTICE-TEMPLATE.md`: base version (`Gforth 0.7.9_YYYYMMDD`) and
  fork release version, all occurrences

Do not rewrite historical mentions (sync history in `README.md`,
`docs/WINDOWS-NATIVE.md`, `docs/WINDOWS-RELEASE-*.md`).

## Generated by the build (gitignored or regenerated; do not edit)

- `engine/config.h`, `envos.fs`, `kernel/version.fs`
  (regenerated by `scripts/build-native.ps1` from `configure.ac`)

## After editing

1. `.\scripts\build-native.ps1 -SkipBootstrap` (or with a bootstrap host)
2. `.\scripts\build-advanced-interactive-image.ps1 -IncludeHistory`
3. Confirm `version-string` prints the new version.
4. Distribution artifacts (ZIP, installer) are built by the maintainer:
   `.\scriptsuild-installer.ps1 -Sign` (needs `CODESIGN_CERT` = certificate
   subject name in the current user's store, and signtool.exe from the Windows SDK).
